# 会社PC・OneDrive運用手順

## 配置

フォルダ全体をOneDriveへ配置し、Excel、BAT、`task_management` フォルダの位置関係を変更しないでください。

OneDriveでは運用フォルダを右クリックし、`このデバイス上で常に保持する` を選択します。

## 初回設定

1. `config.cmd` をメモ帳で開きます。
2. 会社PCで使用するMiniconda環境の `python.exe` を `PYTHON_EXE` に設定します。
3. 個人版とチーム版のExcel名が実際のファイル名と異なる場合は、`workbooks.json` を変更します。
4. `check_environment.bat` を実行します。
5. `PASS` が表示されたら設定完了です。

`PROJECT_ROOT` の設定は不要です。BATが置かれているフォルダを自動的にルートとして使用します。

`config.cmd` にはPythonだけを設定します。

```bat
set "PYTHON_EXE=C:\Users\利用者名\miniconda3\envs\環境名\python.exe"
```

対象Excelの名前は、ルート直下の `workbooks.json` に設定します。日本語のファイル名をWindowsのBATへ直接記述すると会社PCの文字コード設定によって問題が起きる可能性があるため、Excel名はUTF-8のJSONへ分離しています。

```json
{
  "personal": "個人タスク管理_Python連携版.xlsm",
  "team": "複数テーマ階層型タスク管理_Python連携版.xlsm"
}
```

- `personal`: 個人版Excelのファイル名
- `team`: チーム版Excelのファイル名

パスではなく、ルート直下にあるExcelのファイル名だけを指定します。Excelのファイル名を変更した場合は、`workbooks.json` の対応する名前も変更してください。

Excel内のマクロボタンは、ボタンが置かれているExcel自身を対象にするため、上記のファイル名設定には依存しません。`refresh_all.bat`、`update_excel.bat`、`check_environment.bat` など、2つのExcelを一括処理するBATがこの設定を使用します。

## 日常操作

- Excelのボタン、またはルート直下のBATから実行できます。
- `refresh_all.bat`: 両Excelの全体更新
- `export_json.bat`: 両ExcelのJSON Export
- `backup_workbook.bat`: 両Excelのバックアップ
- `validate_workbook.bat`: 両Excelの検証

## 新版への更新

### 目的

`update_excel.bat` は、新しい版のPythonプログラムで必要になったExcel側の構成変更を、現在使用しているExcelへ安全に反映するための保守用BATです。

新版で列・設定項目・書式・集計処理などが追加された場合でも、現在のタスクや進捗を新しい空のExcelへ手作業で移し替えず、使用中のExcelをそのまま更新することを目的としています。

このBAT自体が新版のファイルをダウンロードするわけではありません。新版として配布された `task_management` フォルダやBATを配置した後に、Excel側へ必要な更新を適用する役割です。

### 実行する場面

次の場合にだけ実行します。

- 新版の `task_management` フォルダやBATへ入れ替えたとき
- 更新手順で「`update_excel.bat` を実行してください」と案内されたとき
- Excelの構成バージョンを最新版へ合わせる必要があるとき

通常のタスク入力や日常的な更新では実行不要です。普段はExcelの「全体更新」ボタン、または `refresh_all.bat` を使用します。

### 更新前の準備

1. 更新対象である個人版とチーム版の業務管理Excelを保存します。
2. 更新対象の2つの業務管理Excelを閉じます。業務管理と関係のないExcelは開いたままでも構いません。
3. OneDriveの同期が完了していることを確認します。
4. 新版として受け取った `task_management` フォルダとBATを、現在の運用フォルダへ上書きします。
5. `config.cmd` はPC固有のPython設定なので、配布ファイルで上書きしません。

Excelファイル自体は、更新版の空のExcelで上書きしないでください。現在運用しているExcelを残した状態で更新します。

### 実行手順

1. ルート直下の `update_excel.bat` をダブルクリックします。
2. `Continue? [Y/N]:` と表示されたら、続行する場合は `Y` を押します。
3. 個人版、チーム版の順に更新されます。処理が終わるまで、更新対象の2つの業務管理Excelを開かないでください。業務管理と関係のないExcelは開いても構いません。
4. `Update completed.` と表示されたら更新完了です。
5. 更新後にExcelを開き、通常どおり使用できます。

処理には数分かかる場合があります。画面に結果が表示されるまで、ウィンドウを閉じないでください。

### BAT内部で行われる処理

この処理は次の順番で動作します。

1. 更新前のExcelを `backups` フォルダへ保存
2. Excelに記録された構成バージョンを確認
3. 現在のバージョンから新版までに必要な差分だけを適用
4. ガント、一覧、進捗ログ、日付書式などを全体更新
5. ID、親子関係、必須構成などの整合性を検証
6. すべて成功した場合だけ、更新後のExcelを確定
7. 途中で失敗した場合は、更新前バックアップから自動復元

### 維持されるもの

- 入力済みのタスク、テーマ、進捗、課題、意思決定などのユーザーデータ
- シートの基本的な役割と現在のレイアウト方針
- Excel内のマクロボタン
- `config.cmd` に設定した会社PC固有のPythonパス

ガント、一覧、進捗ログなど、元データから生成される表示用シートは新版の処理で再作成・再集計される場合があります。

### 失敗した場合

`Update failed.` と表示された場合は、更新前のExcelへ自動的に戻されます。

1. Excelを開かずに `check_environment.bat` を実行します。
2. 表示されたエラー内容を確認します。
3. `backups` フォルダに更新前バックアップがあることを確認します。
4. 原因を修正してから `update_excel.bat` を再実行します。

自動復元にも失敗した場合は、`backups` フォルダ内の実行日時が最も新しいファイルを使用して手動復元します。

## エラー時

最初に `check_environment.bat` を実行してください。特に次を確認します。

- `config.cmd` のPythonパス
- 対象環境へのpywin32導入
- OneDriveファイルがオンライン専用になっていないこと
- Excelファイルを同時に複数のPCで開いていないこと
- 会社のマクロ実行ポリシーでブックがブロックされていないこと
