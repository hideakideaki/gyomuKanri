# Phase 1 現状解析と移行計画

## 対象と解析方法

- 正本: `20260825_01/複数テーマ階層型タスク管理_最新版.xlsm`、`20260825_01/個人タスク管理_最新版.xlsm`
- OOXMLを直接読み、シート名、使用範囲、2行目ヘッダー、VBAプロジェクトの存在を確認した。
- VBAはブック作成時に注入したUTF-8管理ソース `vba/`、`personal_vba/` と現行ブックの機能・ボタン構成を照合した。
- 原本は変更していない。実Excelテストは作業用コピーで行った。

## Excel/VBA構成

### チーム版

9シート構成。主入力は `02_タスク`、`05_週次進捗`、`07_課題・リスク`、`08_意思決定`。派生表示はテーマ一覧、週・日ガント、進捗ログ。設定は `09_設定`。

VBAモジュールは `modMain`、`modTask`、`modGantt`、`modProgress`、`modMigration`、`modFormat`、`modUtility`、`ThisWorkbook`。主要Public処理は全体更新、階層構築・検証、ID採番、テーマ集計、週・日ガント、週次進捗生成、進捗ログ同期、JSON、バックアップ、書式設定。

### 個人版

13シート構成。主入力は `01_個人タスク`、`05_週次振り返り`、`10_インボックス`、`12_課題・リスク`、`13_意思決定`。派生表示は今週、今日、予定、完了ログ、週・日ガント、進捗ログ。設定は `07_設定`。

VBAモジュールは `modPersonalMain`、`modPersonalTask`、`modPersonalRecords`、`modPersonalMigration`、`modPersonalUtility`、`ThisWorkbook`。主要Public処理は全体更新、ID採番、今週・今日・予定、ガント、週次振り返り、完了ログ、インボックス、進捗ログ、JSON、バックアップ。

Single Source of Truthは概ね仕様書どおり。ただし旧JSONは派生表（チーム版テーマ一覧・進捗ログ、個人版では旧実装上完了ログ等）も保存しており、再生成可能データとの境界が曖昧だった。v3初期実装では安全のため入力表と管理ログを保存し、完全に再生成可能と検証したビューだけ除外する。

## 現行JSON Export / Import

### チーム版 `HierarchicalTaskManager-2`

- Exportはシートごとの行キーと列見出しを持つため、旧々版の座標方式からは改善済み。
- シート名、キー見出し、行キー、列名、通常文字列、NumberFormatLocalをBase64化。
- ImportはJSON各レコードごとに `FindOrCreateKeyRow` でExcel行を先頭から走査する。計算量は概ね O(M×N)。
- 列は毎フィールド `FindHeader` し、なければ自動追加する。
- IDがなければ行を自動追加する。
- 週次進捗は一般表として扱われ、週ヘッダー名ではあるが専用の週索引はない。
- 保存書式はセル全体の文字色、背景色、太字、斜体、表示形式。`Characters` による部分文字書式は未対応。

### 個人版 `PersonalTaskManager-Keyed-2`

- 1セル1レコード。シート名、キー見出し、行キー、列名、通常文字列、表示形式をBase64化。
- 通常表はレコードごとに `Range.Find`。明示的なID→行索引はない。
- 週次振り返りはレコードごとにIDを `Find` し、その後週列を順次走査する。概ね O(M×(Find+W))。
- 不足ID・列・週を自動作成する。
- セル全体書式のみで、部分文字色は未対応。

## 問題点の判定

| 観点 | チーム版 | 個人版 |
|---|---|---|
| JSON×Excel総当たり | 行探索がO(M×N) | `Find`反復、週列反復あり |
| ID索引 | なし | なし |
| ヘッダー索引 | なし | なし |
| 週索引 | なし | なし |
| 座標依存 | v2主キーは非座標 | v2主キーは非座標 |
| Base64 | 通常文字列を含む | 通常文字列を含む |
| 部分文字色 | 未対応 | 未対応 |
| Import前検証 | 不十分 | 不十分 |
| 不足項目の扱い | 自動作成 | 自動作成 |

## 移行後アーキテクチャ

Excelは入力・表示UIとして維持する。薄いVBAランチャーから `python -m task_management.cli <command>` を呼ぶ。Pythonは、COM操作層、索引・検証・データモデル層、JSON/バックアップ層、team/personal業務層に分離する。

Importは、JSON全体検証 → Excelヘッダー/ID/週索引の一括構築 → 更新計画作成 → Dry Run判定 → バックアップ → 更新 → Rich Text適用 → 保存、の順とする。通常参照は辞書でO(1)、全体はO(N+M)。

## 実装フェーズ

1. Phase 1: 本文書。現状解析と非破壊方針。
2. Phase 2: COMラッパー、モデル、索引、ログ、バックアップ。
3. Phase 3: JSON v3、Dry Run、Merge、Rich Text、v2移行、Round Trip。
4. Phase 4: ID採番、階層・整合性、進捗ログ、集計。
5. Phase 5: 今週・今日・予定・ガント等の派生表示。
6. Phase 6: 実Excelで検証済み処理だけ既存VBAから薄いランチャーへ切替。

優先度A～Cの対象はPython化し、連携版ブックの既存ボタンを薄いVBAランチャー経由のPython呼出しへ切り替えた。旧VBA削除とEXE化は今回実施せず、将来案として残す。
