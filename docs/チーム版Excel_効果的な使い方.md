# 複数テーマ・階層型タスク管理Excelの効果的な使い方

## 1. このExcelで管理するもの

このExcelは、複数テーマの仕事を次の4種類に分けて管理します。

- **テーマ**：一定期間をかけて達成する大きな目的や活動単位
- **タスク**：担当者が期限までに実行する具体的な作業
- **課題・リスク**：進行を妨げる問題、または将来発生する可能性
- **意思決定**：何を、なぜ選んだかという判断の記録

「02_タスク」を作業計画の中心にし、「07_課題・リスク」と「08_意思決定」を補助台帳として使うと、同じ内容を複数箇所へ重複記入せずに管理できます。

## 2. 最初に行う設定

1. 「09_設定」でガント表示開始日・終了日、現在週、エクスポート先を設定します。
2. 「02_タスク」にL1～L4の階層でタスクを入力します。
3. 「階層自動生成」を実行し、テーマID、親タスクID、Level、タスクIDを整えます。
4. 「階層チェック」でID重複や親子関係の不整合がないことを確認します。
5. 「全体更新」でテーマ一覧、週ガント、日ガント、週次進捗を更新します。

黄色の見出しは入力項目、緑の見出しはマクロが設定・更新する項目です。3行目以降は塗り分けではなく、見出しの色を基準に判断します。

## 3. タスク階層の使い分け

階層は細かくしすぎず、「誰が・何を・いつまでに行うか」が判断できる深さまで分解します。

- **L1**：テーマ内の大きな成果や活動群
- **L2**：工程や主要作業
- **L3**：担当を割り当てられる作業単位
- **L4**：必要な場合だけ使う具体的な実行項目

各行には、その行のLevelに対応するL列だけを入力します。例えばL3行ではL3だけを入力し、L1・L2を繰り返し入力しません。親タスクIDなどは階層自動生成に任せます。

タスク名は、できるだけ「成果物または完了状態」が分かる表現にします。

- 良い例：レビュー候補日を関係部署へ提示する
- 良い例：評価方式比較表を完成させる
- 避けたい例：レビュー対応
- 避けたい例：検討

## 4. 課題に書いた内容をタスクにも書くべきか

同じ文章を課題とタスクの両方へコピーする必要はありません。役割を分けて記録します。

### 課題・リスクに書く内容

- 何が問題なのか、または何が起こる可能性があるか
- どのテーマ・タスクへ影響するか
- 影響の大きさ
- 対応方針
- 対応期限と現在の状態

### タスクに書く内容

- 課題・リスクへ対応するために、実際に誰が何をするか
- 作業の期限
- 完了と判断できる成果物や条件

### 両方へ登録する判断基準

課題への対応に具体的な作業が必要なら、課題とは別にタスクを作成します。この場合、「07_課題・リスク」の関連タスクIDへ対応タスクのIDを設定します。

例：

- 課題：関係部署とのレビュー日程が確定しておらず、方式決定が遅れる可能性がある
- 対応タスク：レビュー候補日を3案作成し、関係部署へ提示する

課題には問題と影響を残し、タスクには行動を書きます。これにより、課題が残っているかと、対策作業が完了したかを別々に判断できます。

一方、監視だけでよく、現時点で具体的な作業がないリスクは、課題・リスクだけへ登録します。小さな作業上の注意や、タスクの備考だけで十分な内容を、無理に課題へ登録する必要もありません。

## 5. シートごとの役割

### 01_テーマ一覧

テーマ単位の責任者、状態、マイルストーン、主要課題、総括を確認します。タスクの詳細を重複記載する場所ではありません。管理者が全体状況を短時間で把握するための一覧として使います。

### 02_タスク

作業管理の中心です。担当、状態、優先度、予定・実績日、成果物を管理します。階層を変更した後は階層自動生成と階層チェックを実行します。

### 03_週ガント

L1・L2の中長期計画を確認します。テーマ間の期間重複や、大きな工程の遅れを把握する用途に向いています。

### 04_日ガント

日単位の作業期間を確認します。年・月・日・曜日を縦に分けて表示しています。直近の予定衝突や、担当者の作業集中を確認します。

### 05_週次進捗

各週の実績、判断、次に行うことを文章で残します。「何をしたか」だけでなく、「何が分かり、次に何をするか」まで書くと、翌週の引継ぎに役立ちます。

「全体更新」を実行すると、行は`02_タスク`の現在のタスクID順に同期されます。タスクの追加や行の入れ替えも反映され、既存の進捗本文と部分文字色は「タスクID＋週」によって対応する行へ移動します。

### 06_進捗ログ

週次進捗からマクロで作られる履歴です。原則として直接編集しません。

### 07_課題・リスク

問題とリスクを一元管理します。対応作業がある場合は、関連タスクIDで「02_タスク」と結び付けます。

### 08_意思決定

決定事項だけでなく、背景、検討した選択肢、決定理由を残します。「なぜこの方法にしたのか」を後から説明できる状態にします。

### 09_設定

選択肢、ガント期間、進捗の扱い、バックアップなどの動作条件を管理します。

## 6. 推奨する運用サイクル

### 日常

1. 担当タスクの状態と実績日を更新します。
2. 新しい問題が発生したら課題・リスクへ登録します。
3. 対応作業が必要ならタスクを追加し、関連タスクIDで結び付けます。
4. 重要な判断を行ったら意思決定ログへ残します。

### 週次

1. 「現在週」を確認します。
2. 週次進捗へ、実績・判明事項・次アクションを記入します。
3. 期限超過、遅延、注意状態のタスクを確認します。
4. 未対応・対応中の課題と、期限の近い対応タスクを対にして確認します。
5. 全体更新を実行し、テーマ一覧とガントを確認します。
6. JSONエクスポートまたはバックアップを実行します。

### 月次または節目

1. 完了・中止タスクを確認します。
2. テーマの総括とマイルストーンを更新します。
3. 完了した課題・リスクと意思決定ログを確認します。
4. 不要になった細かすぎるタスクや、重複登録を整理します。

## 7. 重複記載を避ける原則

- テーマの目的・全体状況は「01_テーマ一覧」
- 実行する作業は「02_タスク」
- 問題・不確実性は「07_課題・リスク」
- 判断の経緯は「08_意思決定」
- 毎週の変化は「05_週次進捗」から「06_進捗ログ」

別シートへ同じ文章をコピーする代わりに、テーマIDや関連タスクIDで関連付けます。情報の役割を分けることで、更新漏れや内容の食い違いを防げます。

## 8. バックアップとJSON

- 大きな変更やJSONインポートの前に、必ずバックアップを作成します。
- バックアップは自動削除されません。保存先の空き容量を定期的に確認し、不要なものを利用者が判断して整理します。
- JSONは行番号・列番号ではなく、IDと列名で照合されます。
- IDはレコードを識別する基準なので、既存IDを手作業で変更しないでください。
- JSON取込み後は、階層チェックと全体更新を実行し、件数・親子関係・ガントを確認します。
